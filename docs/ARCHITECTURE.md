# Finger Math — архитектура и план

Тренажёр пальцевого счёта (Чисанбоп): числа 0–99 показываются жестами двух рук.
Левая рука — десятки, правая — единицы. На каждой руке большой палец = 5 (50), остальные четыре = по 1 (10).

## Структура проекта

```
app/src/main/java/com/fingermath/
├─ domain/                    чистый Kotlin, без Android — легко тестировать
│  ├─ gesture/
│  │  ├─ HandGesture.kt       Finger, enum HandGesture (цифра 0..9 -> набор пальцев)
│  │  └─ GestureMapper.kt     число 0..99 -> NumberGesture(tens, ones), и обратно
│  ├─ flash/FlashSession.kt   FlashSettings, NumberSequenceGenerator
│  └─ input/Problem.kt        ArithmeticProblem, InputSettings, ProblemGenerator
├─ ui/
│  ├─ components/             HandView (Canvas, опционально кликабельный), HandGeometry (координаты и hit-test)
│  ├─ flash/                  Режим 1: FlashViewModel (StateFlow) + FlashScreen (Compose)
│  ├─ input/                  Режим 2: InputViewModel + InputScreen
│  └─ theme/
└─ MainActivity.kt            главный экран и простая навигация
```
MVVM: `FlashScreen` только отрисовывает `FlashUiState` и шлёт события во `FlashViewModel`;
вся логика сессии (генерация, тайминг, проверка) живёт во ViewModel и domain.

## Как устроены «ассеты» рук для 0–99

Вместо 100 картинок (или 20 спрайтов) руки **рисуются векторно** на Compose `Canvas`
в виртуальных координатах 100×130:

1. `GestureMapper.toGesture(n)` берёт `n / 10` и `n % 10` и возвращает `NumberGesture(tens, ones)`
   из заранее собранной таблицы на 100 элементов (при смене жеста ничего не считается и не аллоцируется).
2. `HandGesture` — enum на 10 цифр с явной таблицей «цифра -> пальцы». Инвариант
   «сумма весов пальцев == цифра» проверяется в `init` и в юнит-тестах.
3. `HandView(counted: Set<Finger>, mirrored)` рисует 5 пальцев; левая рука — та же геометрия, отражённая.
   Каждый палец анимируется отдельно (80 мс), то есть 20 «спрайтов» заменены одним компонентом.

Почему так, а не VectorDrawable/WebP: нет дублирования ассетов (левая = зеркало правой), нулевой размер
ресурсов, чёткость на любом экране, а главное — состояние каждого пальца независимо, и тот же `HandView`
пригоден для Режима 2, где пользователь переключает пальцы по одному (`HandGesture.fromFingers` уже
даёт обратное отображение). Если дизайнер нарисует «живые» руки, достаточно заменить тело `HandView`
на `painterResource(...)` по тому же `HandGesture`, остальной код не меняется.

## Режим 1 (реализован как прототип)

`Setup -> Countdown(3..1) -> Showing(i/N) -> Answer -> Result`
- Шаги — сложение или вычитание: перед каждым крупно подписывается «Сложение +» / «Вычитание −». Первый шаг всегда сложение, итог не уходит ниже нуля; в настройках можно оставить только сложение.
- Действия: только сложение, сложение и вычитание, только вычитание. В последнем случае первым показывается «Начальное число» (случайное, не меньше числа шагов, до 99), дальше только вычитание.
- Показывать можно жесты, просто цифры или цифры вместе с жестами (`FlashDisplay`): сессия, темп и проверка те же, меняется только то, что рисуется.
- Настройки: число показов (3–20), время на жест (0.5–2.0 с, шаг 0.1), диапазон чисел (1–9 / 1–50 / 1–99).
- Показ и короткая пауза (≤120 мс, руки скрыты) в сумме равны интервалу; одинаковые числа подряд не выпадают.
- Корутина во `viewModelScope`; `Back` и «Настройки» отменяют сессию.
- Макет ограничен по ширине 560dp, руки масштабируются через `aspectRatio` + `weight`.

## Режим 2 (реализован)

`Setup -> Playing(пример i/N) -> проверка -> Дальше ... -> Finished(счёт)`
- Показывается пример «12 + 5 = ?», пользователь нажимает пальцы обеих рук (десятки слева, единицы справа),
  затем «Проверить». Кнопка «Сбросить» опускает все пальцы.
- Нажатие определяется в `HandGeometry.fingerAt` в виртуальных координатах руки (для левой x отражается);
  зоны не зависят от того, поднят палец или сложен.
- Пальцы переключаются свободно, поэтому можно выложить несуществующую комбинацию (например, один мизинец):
  `GestureMapper.toValue` вернёт null, и ответ засчитывается неверным с пометкой «Такого жеста нет».
- Генератор гарантирует, что операнды и ответ лежат в 1..maxValue (до 9 / 50 / 99); действия: +, −, оба.
- После проверки руки блокируются, показывается правильный ответ.

## План расширения

| Что | Куда добавлять |
|---|---|
| Звук | интерфейс `SoundPlayer` в `domain`, реализация на `SoundPool`, вызов из ViewModel |
| Очки, уровни | `domain/score/` + Room/DataStore; `FlashSettings` уже параметризует сложность |
| Таймер на ответ | дополнительная фаза в `FlashViewModel.start()` |
| Локализация | строки сейчас захардкожены по-русски в Compose; вынести в `strings.xml` |

## Сборка

Нужны Android Studio (или SDK + JDK 17). Gradle wrapper в репозиторий не добавлен: откройте проект
в Android Studio или выполните `gradle wrapper` один раз. Тесты: `./gradlew :app:testDebugUnitTest`.
